# 段階5 使いながら磨く

目的: 納品したエージェントを実際の仕事で使う中で出た「ここが違う」を、直せる形で記録し、
頼まれたときに直して測り直す。土台は Anthropic 公式のもの（`claude plugin eval`、skill-creator、
作り方の指針の「使って、気づいて、直して、試す」）を使う。時刻を決めた自動の見回りは予約しない。

## A. 指摘を受けたとき（「ここが違う」「なんか変」など）

1. **直せる粒度まで明確にする。** 次の5点がそろうまで、推奨の答えを添えて1回2問までで聞く。
   すでに会話や Drive からわかることは聞かずに埋める。
   - どの仕事・どの出力か（例: 小テストづくりの、正解の付け方）
   - 実際にどうなったか（出力のその部分をそのまま引く）
   - 本当はどうなってほしいか（直した後の見本を1つ）
   - いつもそうしてほしいのか、その回だけか
   - 直してよい範囲（その部品だけか、全部の部品か）
2. 1行にまとめて見せ、合っているか確かめる:
   「〈仕事〉で〈実際〉になっているのを、〈期待〉にする（いつも／その回だけ）」
3. 改善メモに1件書く。置き場所は利用者の Google Drive の「<プラグイン名>_改善メモ」
   （無ければ作る）。Drive につながっていなければ作業フォルダの `feedback.md`。
   個人名・連絡先は伏せる。

   ```
   ## <日付> <仕事>
   - 実際: …
   - 期待: …（見本: …）
   - 範囲: いつも／その回だけ、<部品名>
   - 状態: 未対応
   ```

## B. 改善を回すとき（「改善して」と頼まれたとき）

1. 改善メモの「未対応」を読む。「その回だけ」のものは直さず、「対応不要」にする。
2. 1件ごとに、その実例から評価の件を1つ足す（`evals/<短い名前>/`。書き方は 3-improve.md と同じ）。
   まず今のプラグインで測り、**直す前に不合格になること**を確かめる。合格したら、メモの理解がずれているので
   A の1に戻って確かめ直す。
3. 直す: 該当する部品の SKILL.md か references を直す。公式の書き方の指針
   （https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices ）に沿い、
   本文は短く、説明文は場面で書く。skill-creator が入っていれば、それで出来を比べてもよい。
4. 測り直す: `claude plugin eval <プラグインのフォルダ> --trust-plugin --runs 2`。
   足した件が合格し、前からある件が落ちていないことを確かめる。直して測るのは最大2回。
5. 段階4の検査（公式の検査と追加の検査）を流し、plugin.json の `version` を1つ上げる。
6. 改善メモの状態を「対応済み <日付>」にし、利用者に報告する:

   ```
   直したこと: <1行ずつ>
   出来: 足した件 ◯/◯ 合格、前からの件 ◯/◯ 合格
   直しきれなかったこと: <無し／件名と理由>
   ```
